# 🛠️ 베프디(BF.D) 환경 세팅

> 바이브코딩을 시작하는 **비개발자 멤버**를 위한 기본 작업 템플릿이에요.
> 어려운 용어는 최대한 빼고, **클로드(Claude)한테 말로 시키는 방법** 위주로 정리했어요.

---

## 👋 처음이라면 여기서 시작하세요

**GitHub, 클론, Claude Code, Vercel… 처음 듣는 말이어도 괜찮아요.** 막히면 클로드에게 `이 말이 무슨 뜻이야? 지금 내 화면에서 뭘 해야 하는지 한 단계씩 알려줘`라고 말해주세요. 클로드를 여는 단계부터 막혔다면 운영진에게 물어봐 주세요.

| 이름 | 지금 알아둘 뜻 |
|---|---|
| GitHub(깃허브) | 프로젝트 파일과 작업 기록을 온라인에 보관하고 공유하는 곳 |
| 레포(저장소) | 프로젝트 하나의 파일과 기록이 모여 있는 공간 |
| 클론(clone) | GitHub 레포를 작업 기록과 함께 내 컴퓨터에 내려받는 것 |
| Claude Code(클로드 코드) | 열어둔 프로젝트 폴더의 파일을 읽고, 말로 요청한 작업을 도와주는 도구 |
| PR | 내가 바꾼 내용을 GitHub에 올려 함께 확인하는 요청. BF.D 진행 기록에도 사용해요 |
| Vercel(버셀) | 만든 웹사이트를 다른 사람이 주소로 열어볼 수 있게 올리는 서비스. 웹 공개가 필요할 때 준비해요 |

### 1. GitHub와 Claude Code 준비하기

- [GitHub](https://github.com/) 계정으로 로그인하고, 운영진에게 받은 **본인 챌린지 작업 레포 주소**가 열리는지 확인하세요. 주소를 못 받았거나 페이지가 안 열리면 운영진에게 알려주세요.
- Claude Code를 아직 설치하지 않았다면 [공식 시작 안내](https://code.claude.com/docs/en/quickstart)를 따라 설치하고 로그인하세요. 아래는 **터미널에서 Claude Code를 여는 방법**으로 안내해요.
- 터미널은 컴퓨터에 명령을 글로 입력하는 창이에요. Mac은 **터미널**, Windows는 **PowerShell**을 검색해서 열면 돼요. 설치 중 막히면 사용 중인 컴퓨터와 화면에 보이는 문구를 운영진에게 알려주세요.

### 2. 본인 작업 레포를 받아서 열기

운영진이 안내한 **본인의 레포 주소**를 내려받으세요. 새 참가자 레포에는 PRD·safe-push 스킬, 공용 Claude 설정, `.gitignore`, `.env.example`이 이미 들어 있습니다.

```sh
git clone <운영진에게 받은 본인 레포 주소>
cd <내려받은 폴더 이름>
claude
```

꺾쇠 부분은 실제 주소·폴더명으로 바꿔주세요. 처음 프로젝트 신뢰 화면이 나오면 본인 레포가 맞는지 확인하고 진행하세요. 별도로 setup-kit을 내려받거나 스킬을 복사하지 않아도 됩니다.

### 3. 바로 PRD 시작하기

Claude Code에서 다음처럼 말하세요:

> PRD 짜줘. 뭘 만들지 같이 정하고 싶어. 처음이니까 한 단계씩 안내해줘.

`.claude/skills/prd-maker/`와 `.claude/skills/safe-push/`는 이 작업 폴더에서 사용됩니다. 스킬이 보이지 않으면 본인 레포를 열었는지 확인하고 새 대화를 시작하세요. Claude Code 설치·개인 로그인은 처음 한 번 필요합니다.

### 4. 기존 레포를 쓰고 있다면

스킬이 없는 기존 레포는 [SETUP.md](SETUP.md)의 별도 설치 절차를 사용하세요. 이미 있는 개인 설정을 덮어쓰지 않습니다. Vercel 배포는 선택이며 아래 안내와 `templates/deploy.yml`을 사용해 별도로 연결합니다. **스킬이 들어 있다고 실제 배포 연결까지 완료된 것은 아닙니다.**

### 5. 계획을 제출하고 작업 이어가기

계획이 나오면 같은 대화에서 **`PR 올려줘`**라고 말하세요. PR은 바뀐 내용을 GitHub에서 함께 확인하는 요청이에요. **BF.D는 커밋만으로 진행을 집계하지 않고 PR을 열어야 해요. 병합 전이어도 열린 PR이면 괜찮아요.**

앞으로도 본인 작업 레포에서 작업하고, 작업물을 올릴 때는 `올려줘`라고 말하면 돼요. 웹사이트 공개가 필요해지면 아래 Vercel 안내를 보거나 클로드에게 `내 작업에 Vercel이 필요해? 필요하면 설정을 한 단계씩 알려줘`라고 물어보세요.

> 💬 어느 단계에서든 `지금 무슨 단계야?`, `이 용어 모르겠어`, `화면에 이렇게 나오는데 다음에 뭐 해?`라고 물어봐도 돼요. 오류를 공유할 때 비밀번호나 비밀 키는 빼주세요.

## 🔐 세팅해줘 — 뭐가 깔리나요?

`세팅해줘` 한마디면 본인 작업 레포에 아래가 준비돼요.

- **🔐 보안 설정 (가장 중요, 필수)** — 클로드가 실수로 비밀 값(토큰·비밀번호)에 접근하거나 위험한 명령(강제 푸시·전체 삭제 등)을 못 하도록 차단룰을 걸어요.
- **safe-push** — `올려줘` 하면 올리기 전에 "이건 올릴까요? 무시할까요?"를 물어봐 줘요. 실수로 비밀 파일이 올라가는 걸 막아줍니다.
- **prd-maker** — `PRD 짜줘` 하면 4주 동안 만들 것을 쉬운 말로 정리해요. 기본 15~20분을 목표로, 준비물 확인부터 내 말로 설명하기까지 함께해요.
- **자동 배포 파일** — `.gitignore`·`.env.example`·자동 배포 설정을 넣어, `올려줘`만 하면 웹에 자동 배포되게 해줘요.

> 💡 이 모든 건 **본인 작업 레포 안(`.claude/` 폴더)** 에만 들어가요. 개인 컴퓨터 전역 설정은 안 건드리고, 레포와 함께 다녀서 다시 받아도 그대로예요.

## 📂 세팅 후 작업 레포에 생기는 것

```
내-베프디-작업-레포/
├── .claude/
│   ├── settings.json     ← 보안 차단룰 (이 레포에서만 적용)
│   └── skills/           ← safe-push, prd-maker
├── .github/workflows/
│   └── deploy.yml        ← push 하면 Vercel 자동 배포
├── .gitignore            ← 비밀 파일(.env 등) 자동 제외
├── .env.example          ← 필요한 비밀 값 이름 견본
└── (여기부터 본인 작업물)
```

### 🔐 자동으로 보호되는 파일 (.gitignore)
아래는 **자동으로 깃 추적에서 제외**돼요. 실수로 커밋해도 깃허브에 안 올라가요:

- `.env`, `.env.local`, `.env.production` (환경 변수, API 키)
- `*.key`, `*.pem`, `*.cert`, `credentials.json` (인증 키·정보)
- `node_modules/`, `.next/`, `dist/`, `build/` (대용량 빌드 파일)

> 자동 보호되긴 하지만, **민감 정보는 절대 코드에 직접 적지 마세요.** 항상 `process.env.토큰이름` 형식으로 참조하세요. (자세한 건 아래 [보안](#-보안--비밀번호토큰-절대-올리지-않기) 참고)

## 🌐 (선택) Vercel 자동 배포 켜기

> 🟡 작업물을 **웹 페이지로 띄워서** 공유하려면 필요해요. 단순 코드 작성/실험만 한다면 **건너뛰어도 됩니다.**
> (세팅 자체는 이거 없이도 완료돼요. 배포만 조용히 건너뜁니다.)

### ① Vercel 가입 + 토큰 발급
1. [vercel.com](https://vercel.com) → **Continue with GitHub** 으로 가입/로그인
2. [토큰 발급 페이지](https://vercel.com/account/settings/tokens) → **Create Token**
   - Token Name: `BF-D-challenge` / Scope: **Full Account** / Expiration: **No Expiration**
3. **CREATE TOKEN** 후 나타나는 토큰을 **즉시 복사** (이 화면 떠나면 다시 못 봐요! 메모장에 임시 보관)

### ② Vercel 빈 프로젝트 만들기 + ID 두 개 얻기
1. [dashboard](https://vercel.com/dashboard) → 우측 상단 **Add New... → Project**
2. 화면을 **맨 아래까지 스크롤** → **"Create Empty Project"** 클릭 → 이름 입력 → **Create**
   > 🚫 위쪽 **Import Git Repository로 가지 마세요!** 반드시 맨 아래 **"Create Empty Project"** 로.
   > 🤔 깃허브 연동을 왜 안 하나요? → 작업 레포에 이미 자동 배포 설정(`deploy.yml`)이 들어가 있어서, push 할 때마다 알아서 Vercel에 배포해줘요. 그래서 Vercel 쪽 연결이 따로 필요 없어요.
3. **ID 두 개** (📌 서로 다른 곳에 있어요):
   - 🅰️ **Project ID** — 프로젝트 → **Settings → General → Project ID** (`prj_xxxx`)
   - 🅱️ **Account ID(=ORG_ID)** — 본인 **계정** → **Settings → General → User ID** (Team 계정이면 Team ID)

### ③ 작업 레포에 시크릿 3개 등록
본인 **작업 레포** 상단 **Settings → Secrets and variables → Actions → New repository secret** 으로 아래 3개 등록:

| Name | Value |
|------|-------|
| `VERCEL_TOKEN` | ①에서 복사한 토큰 |
| `VERCEL_ORG_ID` | ②-🅱️ Account ID (User ID 또는 Team ID) |
| `VERCEL_PROJECT_ID` | ②-🅰️ Project ID |

### ✅ 확인
작업 레포에 아무거나 push → 상단 **Actions** 탭에서 최신 실행이 **✅ 녹색**이면 성공. Vercel 대시보드에서 배포 URL 확인 🎉

## 💻 매일 작업 흐름

```
1. 본인 작업 레포를 클로드로 열고 코드 작성
2. 클로드한테 "올려줘"  → 안전 점검 후 깃허브에 push
3. (Vercel 켰으면) 자동으로 웹 배포 ✨
4. 배포 URL 공유!
```

> ✅ 작업은 **항상 본인 베프디 작업 레포**에서 해요. `올려줘` 하면 거기에 올라가고, 자동 배포까지 이어져요.
> 📤 작업물을 **내 개인 깃허브에도 포트폴리오로** 남기고 싶으면, 클로드한테 **"양쪽 올리기 세팅해줘"** 라고 한 번만 켜두면 돼요(선택). 그러면 `올려줘` 한마디로 양쪽에 올라가요.

## 🔐 보안 — 비밀번호·토큰 절대 올리지 않기

가장 중요한 규칙이에요. **API 토큰, 비밀번호, 시크릿 키** 같은 민감한 값은 **절대 코드에 직접 쓰거나 깃허브에 올리면 안 돼요.** (한 번 올라가면 지워도 인터넷에 흔적이 남아요.)

### ❌ 금지
- 코드에 비밀번호·API 키·토큰을 **직접 적기**
- `.env` 같은 민감 파일을 **강제로 커밋**

### ✅ 권장
토큰 / 키 / 비밀번호는 아래 중 한 곳에 등록하세요:
- **GitHub Secrets** (작업 레포 → Settings → Secrets and variables → Actions)
- 또는 **Vercel Environment Variables** (Vercel 프로젝트 → Settings → Environment Variables)

그리고 코드에서는 **`process.env.토큰이름` 형식으로만** 참조하세요.

```bash
# .env 파일 (이 파일은 깃허브에 올리지 않음!)
DISCORD_TOKEN=실제_토큰_값
NOTION_TOKEN=실제_토큰_값
```
```js
// 코드에서는 직접 쓰지 말고, 환경 변수로 불러와서 사용
const token = process.env.DISCORD_TOKEN
```

> 어떤 값이 필요한지는 `.env.example` 에 **값은 빼고 이름만** 적어두면 팀원이 참고하기 좋아요. (세팅 때 견본이 하나 들어가요.)
> 헷갈리면 클로드한테 **"이 프로젝트 보안 점검해줘"** 라고 하세요.

## 🆘 안 될 때 (트러블슈팅)

- ❌ **스킬이 안 먹혀요** → 스킬은 **본인 작업 레포**에서, **새 대화창**부터 인식돼요. 세팅 레포 말고 작업 레포를 열었는지 확인하세요.
- ❌ **Actions 워크플로우 실패** → 작업 레포 상단 **Actions** 탭에서 빨간 ❌ 클릭해 로그 확인
- ❌ **"Vercel 시크릿이 아직 등록되지 않았어요" 경고** → 위 [Vercel ③ 시크릿 등록](#-작업-레포에-시크릿-3개-등록) 다시 확인 (안 쓸 거면 무시해도 됨)
- ❌ **"충돌(conflict)이 났다"** → 같은 파일을 여러 명이 동시에 바꿨을 때 생겨요. 클로드한테 "충돌 났는데 도와줘"
- ❌ **그래도 안 되면** → 운영자에게 문의 🙋

> 무엇이든 막히면 클로드한테 **화면에 보이는 걸 그대로** 말해주세요. "~하려는데 ~라고 떠요" 처럼요. 🙂

## ❓ 자주 묻는 질문

**Q. 안 올린 파일은 사라지나요?**
> 아니요! 내 컴퓨터엔 그대로 있어요. 깃허브(인터넷)에만 안 올라가는 거예요.

**Q. 실수로 비밀번호·토큰을 올렸어요. 어떡하죠?**
> 당황하지 말고 클로드한테 그대로 말하세요. 특히 토큰을 올렸다면 즉시 그 값을 **새로 발급(재발급)** 받아야 해요.

**Q. Vercel 꼭 써야 하나요?**
> 아니요. 작업물을 웹으로 보여줄 게 아니면 `세팅해줘`만 하고 Vercel은 건너뛰세요. 세팅은 그것만으로도 완료돼요.

**Q. 꼭 클로드한테 시켜야 하나요? 직접 하면 안 되나요?**
> 익숙해지면 직접 해도 되지만, 처음엔 **말로 시키는 게 가장 안전**해요. 확인 단계가 자동으로 들어가서 실수를 막아줘요.

## 운영진: 기본 템플릿 유지보수

`skills/`와 `templates/`가 원본입니다. 원본을 수정한 뒤 `node scripts/sync-starter.mjs`를 실행하고, 설치된 파일도 같은 PR에 포함하세요. `node scripts/sync-starter.mjs --check`로 누락을 검사합니다. 이 스크립트는 **setup-kit 유지보수용**이며 참가자의 기존 개인 설정을 업데이트하는 용도로 실행하지 않습니다.

새 레포는 GitHub의 Template repository 기능으로 기본 브랜치를 복사합니다. 나중에 템플릿을 고쳐도 이미 만든 참가자 레포는 자동으로 바뀌지 않습니다.
